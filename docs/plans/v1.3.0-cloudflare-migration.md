# v1.3.0 遷移計畫：Vercel → Cloudflare Pages（免費 ＋ 多人協作）

> **狀態：暫緩（2026-11-15 決定）**
> 專案負責人決定先不遷移，改為把 Vercel 帳號直接交給合作組員使用。
> 技術準備已完成並保留在 main：`wrangler.toml`、`public/_headers`、`public/_redirects`、
> `functions/api/[[route]].js`，以及一個可用的 Pages 專案（`2026-s2c-trees.pages.dev`，API 仍代理回 Vercel）。
> 若日後恢復遷移，從「P2：移植 API」繼續即可。

## 1. 為什麼要搬

Vercel 免費（Hobby）方案**不支援協作**：一個團隊只有 1 位成員（就是擁有者）。
官方社群回覆原文：

> "Hobby teams do not support collaboration… Hobby plans only allow deployment [by the owner]."

要兩人以上同時協作只能升級 **Pro：US$20／人／月**，兩個人就是 **US$40／月**。
老師要求的「兩人共同維護」在免費 Vercel 上做不到，所以要把部署平台換掉。

**資料庫（Neon）不用搬**：Neon 免費方案的組織成員數**無上限**，直接邀請同學即可。

## 2. 候選平台比較（2026-11 查證）

| 平台 | 免費方案多人協作 | 免費額度 | 結論 |
|---|---|---|---|
| **Cloudflare Pages ＋ Workers** | ✅ 帳號可加成員並指派角色（Roles／Policies） | Workers：**100,000 請求／日**、CPU 10ms／請求、100 個 Worker；Pages：**500 次建置／月**、單站 20,000 檔案 | ✅ **建議** |
| Netlify | ⚠️ 免費只能加 **Reviewer（唯讀回饋）**，要真的加成員需升級 | 免費 300 credits／月 | ❌ 不符合 |
| Render | ❌ 成員數隨方案，免費等同單人 | 免費 instance 會休眠 | ❌ 不符合 |
| Firebase（Google Cloud） | ✅ IAM 可多人 | Hosting 免費；但 Functions 需要 Blaze（按量計費） | ⚠️ 可行但要綁信用卡 |
| GitHub Pages | ❌ 純靜態，沒有 API | — | ❌ 不符合 |

> Cloudflare 的成員上限在邀請畫面會顯示；免費帳號可先邀請同學試一次，若被限制再評估。

## 3. 目標架構

```
GitHub repo（不變）
   └─ Cloudflare Pages（免費）
        ├─ 靜態資產：public/（HTML／CSS／JS／657 張照片）
        └─ Functions：functions/api/[[route]].js（取代 api/[[...route]].js）
              ├─ Neon PostgreSQL（不變，HTTP driver 在 Workers 可用）
              └─ Cloudflare R2（取代 Vercel Blob，免費 10 GB）
```

- 網域：先用 `*.pages.dev`，穩定後再把 `old-trees-mylearning.vercel.app` 的對外連結換掉
- 協作：Cloudflare 帳號 → Members → 邀請同學（角色：Pages 專案編輯）
- 版本紀錄、PR 流程、測試全部不變

## 4. 要改的東西（逐項對照）

| 現況（Vercel） | 遷移後（Cloudflare） | 工作量 |
|---|---|---|
| `api/[[...route]].js`（Node handler） | `functions/api/[[route]].js`（fetch handler） | 中：改寫入口，路由邏輯 `lib/routes/*` 可沿用 |
| `lib/http.js`（Node 風格 req/res） | 改成 Web `Request`／`Response` | 中 |
| `@vercel/blob` 上傳 | R2（S3 相容 API，`aws4fetch` 約 10 KB） | 小 |
| `vercel.json` 的 headers（CSP 等） | `public/_headers` | 小 |
| `vercel.json` 的 rewrite（`/api/tree/:no`） | `public/_redirects` 或 Functions 內處理 | 小 |
| GitHub Actions 每日抓取 | 不變（動作在 GitHub 上跑） | 0 |
| Service Worker、前端 | 不變 | 0 |
| 環境變數（`DATABASE_URL`、R2 金鑰） | Cloudflare Pages → Settings → Environment variables | 小 |

## 5. 分階段（每階段都可獨立驗證、可回滾）

| 階段 | 內容 | 驗收 |
|---|---|---|
| **P0** | 建 Cloudflare 帳號、Pages 專案、邀請同學 | 兩人都在 Members 名單 |
| **P1** | 只部署靜態站（`public/`）到 Pages | `*.pages.dev` 首頁、地圖、專題導覽正常（API 先指向現有 Vercel） |
| **P2** | 移植 API 到 Pages Functions（先做 `/api/health`、`/api/trees`） | 兩支端點回傳與 Vercel 一致 |
| **P3** | 其餘 16 支端點 ＋ 照片改存 R2 | 全站功能對照清單逐項通過 |
| **P4** | 對外網址切換（Wiki、README、Release 說明） | 舊網址 301 到新站 |
| **P5** | Vercel 專案保留 30 天作回滾，之後刪除 | — |

## 6. 風險

| 風險 | 影響 | 對策 |
|---|---|---|
| Workers 免費 CPU 10ms／請求 | 複雜查詢可能超時 | 先量測 `/api/priority`（最重的一支）；必要時把那支改成預先計算 |
| Pages Functions 冷啟動 | 首次請求慢 200–800ms | 可接受；必要時加 Cron 保溫 |
| R2 簽名實作 | 上傳照片的程式要改 | 用 `aws4fetch`，體積小、無依賴 |
| 網域切換 | 老師手上的舊連結失效 | 保留 Vercel 專案並在舊站放提示，或直接把舊網域 301 |
| 免費額度 | 100k 請求／日、10 GB 照片 | 目前流量遠低於上限；照片 46 MB |
