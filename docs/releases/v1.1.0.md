# v1.1.0 — 資料層遷移到 Neon ＋ 照片改存 Vercel Blob

發佈日期：待部署驗收（程式已完成，尚未上線）

## 為什麼改

Supabase 免費方案「7 天低活動就暫停」，2026-11-14 實際發生：`/api/trees` 回 503 `db_unreachable`，網站資料全空，需要專案擁有者手動 Resume。

Neon 的行為相反：專案不會被暫停，閒置 5 分鐘只是 compute 休眠，下一個查詢自動喚醒（實測冷啟動約 480ms）。

## 改了什麼

| 項目 | 之前 | 之後 |
|---|---|---|
| 資料庫 | Supabase（PostgreSQL 17，ap-south-1） | **Neon**（PostgreSQL 17，**ap-southeast-1 新加坡**） |
| 驅動 | `@supabase/supabase-js`（PostgREST） | **`@neondatabase/serverless`**（HTTP driver，`sql.query()`） |
| 照片 | Supabase Storage（`field-photos` bucket） | **Vercel Blob**（`field-photos/` 前綴，region `hkg1`） |
| 權限模型 | RLS ＋ anon／service_role 兩把金鑰 | 單一連線角色，所有查詢經 Vercel Functions |
| 綱要 | `supabase/init.sql`（含 RLS、Storage bucket） | **`db/001_schema.sql`**（8 表、3 檢視、6 函式、224 筆種子） |
| 環境變數 | `SUPABASE_URL`／`SUPABASE_SERVICE_ROLE_KEY` | **`DATABASE_URL`**／`BLOB_READ_WRITE_TOKEN` |

`DATA_SOURCE` 由 `supabase` 改為 `neon`；未設定 `DATABASE_URL` 時仍走內建快照（示範模式），行為與過去相同。

## 部署前必做

1. Vercel → `old-trees` → Settings → Environment Variables → 新增 **`DATABASE_URL`**（值在專案的 `.env.local`；Neon Console → Connect 可重新取得）
2. `BLOB_READ_WRITE_TOKEN` 已由 Blob store（`old-trees-photos`，hkg1）自動寫入 production／preview／development
3. 先看 Preview 部署的 `/api/health` 是否回 `data_source:"neon"`、`tree_count:658`，再合併到 `main`

## 回滾

Supabase 專案先不刪；把 `SUPABASE_*` 環境變數改回來、部署 v1.0.6 的 commit 即可回復。驗收通過後再刪 Supabase 專案（同時讓 2026-09-24 外洩的舊 `service_role` 金鑰失效）。
