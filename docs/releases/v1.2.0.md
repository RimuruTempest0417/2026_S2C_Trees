# v1.2.0 — 併入世界地圖專題（與同學的作品合併）

老師建議把兩個人的作品合併，這一版把同學的〈世界地圖：從全球一路放大到每一棵古樹〉併進本站，掛在 **`/partner/`**，主站導覽列新增「世界地圖」入口。

## 併入了什麼

| 內容 | 大小 |
|---|---|
| `public/partner/index.html` | 24.6 KB（原本是 419 KB 單檔） |
| `public/partner/app.js` | 405 KB（原本內嵌在 HTML 裡的 354 KB script） |
| `public/partner/相片/` | 657 張 JPEG，48 MB |

他的頁面原本是一個完全自足的單檔：資料、樣式、腳本全部內嵌，地圖直接用 ArcGIS 線上圖磚（`server.arcgisonline.com`，免金鑰），自己寫 pan/zoom，沒有第三方套件、沒有 CDN。

## 為什麼不能「原檔直接搬」

本站的 CSP 是嚴格的 `script-src 'self'`（v1.0.6 起就沒有放寬過）。原檔搬進來會踩兩個雷：

| 問題 | 後果 | 處理 |
|---|---|---|
| 354 KB 內嵌 `<script>` | 整個頁面的 JS 被 CSP 擋掉，畫面只剩靜態 HTML | 抽出成 `app.js`，改用 `<script src="./app.js">` |
| 卡片用 `innerHTML` 組出 `onerror="imgFix(...)"` | 每張縮圖都報 `Executing inline event handler violates…`，圖片載入失敗時沒有備援 | 改成 `data-fix` 屬性 ＋ `document.addEventListener('error', …, true)` 委派監聽 |
| ArcGIS 圖磚網域不在 `img-src` | 世界地圖整片空白 | `vercel.json` 的 `img-src` 加上 `https://server.arcgisonline.com` |

**沒有放寬 `script-src`**：寧可改他的程式三行，也不要把 `'unsafe-inline'` 加回去。

## 驗證

```
npm test                  → 399 項全過（新增 tests/partner.test.js 6 項）
npm run check             → 通過
本機 CSP 模擬（實際標頭）  → 0 個 CSP 違規、0 個 console 錯誤
ArcGIS 圖磚               → 實際發出 12/3338/1788 等 tile 請求並載入
渲染後 DOM                → 24 KB → 234 KB（證明 JS 真的執行）
```

新增的守門測試（`tests/partner.test.js`）：

1. 專題頁只能用外鏈 script（`app.js`），且檔案要 > 300 KB
2. HTML 與 **app.js 產生的字串**都不得含 inline 事件屬性
3. CSP 的 `img-src` 必須有 `server.arcgisonline.com`，且 `script-src` 不得出現 `unsafe-inline`
4. 657 張照片齊全
5. 主站導覽列有 `/partner/` 入口
6. 專題頁不得出現「作業」二字

## 兩個後續要留意的地方

- **照片來源與授權**：657 張照片是同學提供的，需確認來源（若取自市政署自然網，頁面上要有出處標註）。這件事待與同學確認後補上。
- **Service Worker**：`public/partner/` 沒有列入預載清單（避免把 48 MB 照片塞進快取），所以離線時該頁不可用——這是刻意的。

## 升級注意

- 沒有任何 API 或資料庫變更，Neon 不需要動作。
- 主站其他頁面完全不受影響；CSP 只多了一個圖片來源。
