# v1.2.0 — 與第二名同學的作品整合

老師建議把兩個人的作品合併。這一版**不是並列兩個入口**，而是把對方真正有價值的部分吸收進本站，變成一個產品。

## 先說結論：兩份資料其實是同一份

逐欄比對 658 筆：

| 比對項目 | 結果 |
|---|---|
| 樹號 | 658 / 658 對應 |
| 樹種、分級、健康、樹齡、高度、堂區、經緯度 | **0 筆差異** |
| 照片編號 | **658 / 658 相同** |

所以「資料比較後保留」這件事不需要做——原本就是同一套官方名錄。真正值得吸收的是**呈現方式**。

## 吸收了哪三樣

### 1. 世界地圖（`#/map` 的預設模式）

對方自寫的 SVG 地圖引擎：全球 → 珠三角 → 澳門 → 單棵。

- 新檔 `public/js/worldmap.js`：Web Mercator ＋ 單一 `<g>` 變換；滾輪以游標為中心縮放、拖曳、雙擊、+/−、雙指縮放
- 低倍率：119 國國界；中倍率：珠三角輪廓；高倍率：8 個堂區界線 ＋ 658 個樹點（綠／黃／紅＝健康）
- 與本站功能連動：篩選即時更新樹點、點樹點開原本的詳情、`?tree=544` 自動聚焦
- 原本的 Leaflet 平面地圖保留為 `[世界地圖｜平面地圖]` 的第二模式（街區要看街道時用）

### 2. 高解析照片（657 張）

同一批官方照片，對方版本解析度更高：

| | 之前 | 現在 |
|---|---|---|
| 單張 | 約 30 KB | 約 70 KB |
| 總量 | 19.3 MB | 46.4 MB |
| 實測（#508） | 32,996 bytes | 79,649 bytes |

路徑與檔名不變（仍以樹號命名），只換內容。

### 3. 專題導覽（`#/story`，第 13 個分頁）

對方原有的 6 章敘事結構，改寫成引導式導覽，**所有數字執行時用本站資料重算**（不照抄原文）：

1. 各堂區古樹數目分佈 —— 長條＋圓環，點擊帶 `parish` 到地圖
2. 樹種結構 —— 56 種；心葉榕一種佔 54.1%
3. 樹齡與樹高結構 —— 99.2% 逾百年；最老 #544 海南蒲桃 515 年
4. 健康與保護級別 —— 各堂區健康比例 100% 堆疊
5. 古樹圖鑑入口 —— 欄位完整度＋四個入口（不重做 658 張卡片牆）
6. 資料來源 —— 市政署自然網、第 279/2025 號行政長官批示、第 11/2013 號法律

### 順帶修正對方原文的一個結論

對方寫「花地瑪堂區健康比例最低」，用本站官方 `health` 實算是 **望德堂區 14.9%**（花地瑪 18.7%）。導覽頁照實際資料呈現。

## 移除了什麼

`/partner/` 獨立頁（含 657 張照片副本）**已刪除**。它的內容全部被吸收，留著只會變成第二個產品。

技術上原本還有兩個坑要處理（都解決了）：

| 問題 | 處理 |
|---|---|
| 354 KB 內嵌 `<script>` 會被 `script-src 'self'` 擋掉整頁 | 把地圖邏輯重寫成 `public/js/worldmap.js` 模組 |
| 卡片用 `innerHTML` 組出 `onerror="imgFix(...)"` | 不沿用該寫法；新模組全程用 `addEventListener` |

**沒有放寬 `script-src`**：`'unsafe-inline'` 一次都沒有加回去。
