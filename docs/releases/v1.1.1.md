# v1.1.1 — 安全收尾與 GitHub 協作守門

這一版**沒有新增功能**，全部是「把專案當成正式專案在管」的收尾：安全警示清零、分支有保護、依賴沒有已知漏洞。

## 為什麼要這一版

v1.1.0 上線後，GitHub 的 Security 頁面同時亮起三個紅點：1 筆 Dependabot 高風險、1 筆 secret scanning、Code scanning 未啟用。另外 repo 轉為 public 後，`main` 沒有任何保護——任何人（包括自己）都能直接 push。

三個問題都在這一版處理完，並且留下判讀紀錄，方便日後覆核。

## 改了什麼

| 項目 | 內容 |
|---|---|
| **安全政策** | 新增 `SECURITY.md`：支援範圍、私下回報管道（Private vulnerability reporting）、處理時效、已知設計取捨 |
| **CodeQL** | 啟用 Default setup（`actions`／`javascript`／`typescript`／`python`，每週掃描）；首掃 8 筆全部判讀並關閉，紀錄見 `docs/security/codeql-triage-2026-11-14.md` |
| **依賴漏洞** | `@vercel/blob → @vercel/oidc → @vercel/cli-config → zod@4.1.11` 以 `overrides` 提到 `^4.6.6`（實際 4.6.7）；`npm audit` 由 4 high → **0** |
| **分支保護** | 新增 ruleset `main-protection`（必須開 PR、1 人批准、需 Code Owners 審查、禁止刪除與 force push）與 `develop-protection`（禁止刪除與 force push） |
| **自動刪分支** | 關閉 `Automatically delete head branches`——它會把 `develop → main` 那個 PR 的來源分支一併刪掉 |
| **歷史清理** | 以 `git filter-repo` 移除歷史中的 Chrome 設定檔目錄（484 檔、6.7MB）與舊 `.env.example` 金鑰字串；45 個 tag／Release 重建 |
| **文件** | 新增 `docs/github-support-purge-request.md`（若日後要請 GitHub 清除舊快取，稿子已備） |

## 升級注意

- 服務工作者的快取版本已升到 `v1.1.1`；若瀏覽器仍顯示舊版，重新整理一次即可。
